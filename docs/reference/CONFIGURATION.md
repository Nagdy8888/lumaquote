# Configuration and native process operation

This is a safe variable-name reference derived from `luma/core/config.py`, Vite
configuration and the repository scripts. It contains no populated credentials.
Use [LOCAL_DEVELOPMENT.md](../../LOCAL_DEVELOPMENT.md) and
[README setup](../../README.md#run-locally) for the installation sequence.

## Loading and restart semantics

`Settings` loads root `.env`, then `.env.local`; the local file overrides earlier
file values. Process environment overrides dotenv values through Pydantic Settings.
Unknown settings are ignored. `settings()` caches its validated object, so editing
a file does not reconfigure a running API/worker. Restart the native process;
tests/setup clear the cache deliberately when their controlled environment changes.

SecretStr prevents accidental plain representation of marked fields; it does not
make logging `get_secret_value()` safe. Never print populated dotenv files, DSNs,
clasp credentials, HTTP authorization headers or private restoration payloads.
`.env.example` is a minimal safe template, not the complete list of supported fields.

## Supabase and database identities

- `SUPABASE_URL`: defaults to this project's loopback API `http://127.0.0.1:55321`.
- `SUPABASE_ANON_KEY`: public API credential used with the staff token for Auth
  verification. It is not an administrative key or company authority.
- `SUPABASE_SERVICE_ROLE_KEY`: backend-only private object/provisioning credential.
- `DATABASE_URL`: privileged local setup/test DSN; not the normal runtime identity.
- `LUMA_API_DATABASE_URL`: restricted staff API DSN generated by setup.
- `LUMA_WORKER_DATABASE_URL`: restricted trusted worker/checkpoint DSN generated
  by setup; broader cross-company role, never browser configuration.
- `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`: the only intended Supabase values
  for the browser bundle. Vite's public prefix must never be attached to a secret.

`npm run db:configure` captures local CLI status into ignored `.env.local` only
after verifying API port 55321 and database port 55322 on loopback. `npm run setup`
also guards the database target before migrations/provisioning. The normal database
context uses the restricted DSNs and a five-second connect timeout. These setup
guards do not certify an arbitrary future production configuration.

Local ports are API/Auth/Storage 55321, PostgreSQL 55322, Studio 55323 and test mail
55324. Native staff API is 8001, optional Google gateway 8002, Vite dev 5173 and
Vite preview 4173. Browser tests choose their own temporary loopback app ports.
Do not expose Supabase administration or the staff API through a callback tunnel.

## Paid AI policy

- `OPENAI_API_KEY`: private provider credential; empty by default.
- `OPENAI_MODEL`: `gpt-6-luna` for structured requirements and label reading.
- `TRANSCRIPTION_MODEL`: `gpt-transcribe` for English voice input.
- `EMBEDDING_MODEL`: `text-embedding-3-small`, with adapter dimensions fixed to 1536.
- `ENABLE_PAID_AI`: false by default. Normal graph/media processing uses the
  documented offline/manual paths until deliberately enabled.
- `TOTAL_BUDGET`: estimated USD 25, shared globally in the current local policy.
- `DAILY_BUDGET`: estimated USD 5 per UTC day; unresolved work remains counted
  across midnight.
- `RESERVATION`: estimated USD 0.25 primary/run maximum. Retrieval gets at most
  USD 0.01 within that same maximum, not additional unlimited allowance.

These defaults are Settings values, not necessarily explicitly present in the
minimal template. Model adapters reject unsupported configured models rather than
silently selecting a costlier fallback. Changing a string does not establish a
compatible SDK schema, context bound, price assumption or quality result.
Operator indexing additionally requires its explicit execute command; do not
assume the worker's paid-toggle policy is the only possible operator admission
boundary. See [catalog operation](CATALOG.md).

## Tracing policy

`LANGSMITH_API_KEY`, `LANGSMITH_PROJECT` and `LANGSMITH_ENDPOINT` configure the
optional masked job tracing (decision D24). The Settings default project is quotation-assistant
and endpoint is the LangSmith API. `LANGSMITH_TRACING` defaults false in Settings;
the minimal example explicitly opts it to true, but a key and available account
allowance are still required for export.

When enabled, each worker job is exported as one masked trace with full inputs
and outputs of its graph steps and model calls; secrets, tokens, signatures and
phone numbers are masked and media bytes are dropped. Outside the worker (tests,
harness, scripts) tracing is forced off regardless of `LANGSMITH_TRACING`. Contract,
masking rules and limits: [agent runtime: trace privacy](AGENT_RUNTIME.md#trace-privacy-and-debugging).
Quota or network failures are logged by class and never stop quotation work; they are
not solved by inventing a new project, retrying indefinitely or claiming configured
means verified.

## Messaging and Google configuration

`WHATSAPP_TOKEN`, `WHATSAPP_APP_SECRET` and `WHATSAPP_VERIFY_TOKEN` are backend-only secrets.
`WHATSAPP_PHONE_ID` and `WHATSAPP_COMPANY_ID` bind the one receiving number to one tenant (the
webhook refuses everything until all five are set). `WHATSAPP_TEST_RECIPIENTS` is the comma-separated
allowlist gating inbound senders and outbound recipients; empty admits nobody. `WHATSAPP_GRAPH_VERSION`
defaults to `v26.0` and must be confirmed at live setup. `ENABLE_LIVE_WHATSAPP` defaults false and
is the master gate for real sending. The adapter is implemented but verified only against a mock
Graph transport; see [WhatsApp channel](WHATSAPP.md). These fields do not create a free-message
entitlement or an authorized recipient.

`GOOGLE_SHEET_ID`, `GOOGLE_COMPANY_ID` and `GOOGLE_CALLBACK_SECRET` bind the signed
receiver to one approved workbook/company. The secret is backend-only and must
match private GAS Script Properties. Current workspace status requires all three
and the member's exact company mapping, and reports configured/unverified.

GAS uses `LUMA_SPREADSHEET_ID`, `LUMA_COMPANY_ID`, `LUMA_CALLBACK_URL` and
`LUMA_CALLBACK_SECRET` as private Script Properties. Backend Google client IDs,
client secrets and refresh tokens are not part of the approved current design.
Account actions, trigger installation and changing a tunnel destination remain
explicit setup tasks documented in [Google synchronization](GOOGLE_SYNC.md).

## Private generated files and reproducibility

`.local/staff-access.json` contains generated local staff access; do not paste its
password into docs or capture it on screen. `.clasp.json` maps the intended script
project; clasp account credentials are also ignored. `supabase/.temp` contains
private CLI logs/restore configuration. `.local/checks` contains verification logs
and summary, while `.local` also contains synthetic screenshots/canary artifacts.

Reproducible dependency sources are `requirements.lock.txt` and `package-lock.json`.
`pyproject.toml` and frontend `package.json` describe dependencies, but broad ranges
do not identify every installed version. The recorded runtime is Python 3.12;
GitHub CI uses Node 22/Python 3.12. Native Windows evidence and Ubuntu CI evidence
must remain separately identified.

## Safe routine operation

Start the local stack with `npm run db:start`, configure it, then run setup. Start
API, UI and worker as native processes in separate terminals. Docker is used for
Supabase and the short-lived offline parser, not every application process.

The start helper checks this project's named containers and preserves volume
mounts while restricting published ports to loopback. It retains Kong runtime
files if container recreation is needed, reconnects dependent database clients
after database recreation and waits for running/healthy status. A healthy Docker
engine alone is not proof Auth/Storage are ready.

`npm run db:stop` is ordinary local shutdown, not a reset. Keep all named volumes
and the separate Smart RAG project's resources intact. For a failed Docker/WSL
engine, inspect the historical recovery notes; do not factory-reset Docker,
delete a VHDX or rewrite migrations as a routine workaround.

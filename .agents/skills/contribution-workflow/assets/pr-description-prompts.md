# PR description prompts

Lead with the concrete problem and resulting user behavior. Follow the repository template when present.

Include only sections that help assess the change:
- What changed and why, with a trigger and before/after example when useful.
- Reproducible validation commands and results, including relevant failure cases.
- UI evidence for visual changes, or an honest statement that visual checks were unavailable.
- Migration, operational, or rollback implications when applicable.
- Actual issue references and unresolved material limitations.

Scale detail to complexity. Do not add a ticket, screenshot claim, passed check, deployment, or release result that does not exist.
